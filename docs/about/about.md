# About
{: .no_toc }

The Encoded Archival Standards (EAS) Suite includes the three standards EAD, EAC-CPF and EAC-F. They provide the different XML formats to use for giving the description of the answers to the Who (EAC-CPF), Why (EAC-F) and What (EAD) of records in XML.

The Encoded Archival Standards Best Practices Guide, as a companion to the EAS Tag Libraries, is a living document created collaboratively by members of the [Technical Subcommittee on Encoded Archival Standards (TS-EAS) of the Society of American Archivists (SAA) Standards Committee](https://www2.archivists.org/groups/technical-subcommittee-on-encoded-archival-standards-ts-eas) and the user community of the EAS Suite.

## Sub-Teams

The TS-EAS is made up of several sub-teams which manage various responsibilities, such as development, creation, maintenance, and revision of each standard.

Current Standing Sub-Teams
- [EAD](https://github.com/SAA-SDT/TS-EAS-subteam-notes/wiki/EAD-Sub-Team_)
- [EAC-CPF](https://github.com/SAA-SDT/TS-EAS-subteam-notes/wiki/EAC-CPF-Sub-Team)
- [EAC-F](https://github.com/SAA-SDT/TS-EAS-subteam-notes/wiki/EAC-F-Sub-Team)
- [Outreach and Communications](https://github.com/SAA-SDT/TS-EAS-subteam-notes/wiki/Outreach-and-Communications-Sub-Team)
- [Schema](https://github.com/SAA-SDT/TS-EAS-subteam-notes/wiki/Schema-Sub-Team)

Additional working groups are formed with members across the Sub-Teams to deliver content:
- **Documentation Task Force:** Responsible for maintaining Tag Libraries and Best Practices Guide
- **Editorial Board:** Responsible for creating and vetting articles for Best Practices Guide

## Navigation of site

This site is organized into general categories listed in the sidebar: 
- [General Guidelines](https://saa-sdt.github.io/EAS-Best-Practices/docs/general-guidelines) provides editorial guidance for different scenarios in descriptive practice.
- [EAS Suite](https://saa-sdt.github.io/EAS-Best-Practices/docs/eas-suite) contains separate pages for each of the EAS standards with links to their respective hosted websites, tag libraries, schema files, and xml example files.
- [Control](https://saa-sdt.github.io/EAS-Best-Practices/docs/control) contains information about metadata that is included or defined in the `<control>` element of the EAS standards. Typically contains administrative metadata for the record itself, as opposed to descriptive metadata of records, creators, and/or functions.
- [Names or Identity](https://saa-sdt.github.io/EAS-Best-Practices/docs/names-or-identity) refers to the creation and assignation of creators, as they are defined in the EAC-CPF standard.
- [Description](https://saa-sdt.github.io/EAS-Best-Practices/docs/description) contains articles about various descriptive elements used in the EAS Suite. This includes the use of dates, chronological lists, places, etc.
- [Functions](https://saa-sdt.github.io/EAS-Best-Practices/docs/function) refers to descriptions of functions and use across the EAS Suite.
- [Relations](https://saa-sdt.github.io/EAS-Best-Practices/docs/relations) contains articles about encoding relationships across the EAS Suite and within the respective standards.
- [References](https://saa-sdt.github.io/EAS-Best-Practices/docs/references) provides guidance around the use of references across the EAS Suite, such as internal referencing in a record, making external references, and linking to external vocabularies and their sources.
- [Crosswalks](https://saa-sdt.github.io/EAS-Best-Practices/docs/crosswalks) contains metadata crosswalks of EAS standards to other established descriptive standards, such as ISAAR(CPF) and RiC.

## Submitting issues (including content)

Individuals with a GitHub account may [submit an Issue in the GitHub repository.](https://github.com/SAA-SDT/EAS-Best-Practices/issues) There are three templated forms to choose from:
- New Page Proposal
- Suggestion for an existing page
- Value term submission (for TS-EAS Sub-Teams)

These templates have been formatted to provide necessary information about the content proposed. They are written in markdown with directions for selecting options and adding text. 

The issues will be reviewed by the Editorial Board. The issues are approved for final publication on this site after an editing process guided by the Editorial Board.
